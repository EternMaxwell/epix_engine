# Bevy Mesh and Core Pipeline — Epix Match Status

Reference: Bevy 0.18.0 sources in `tmp/bevy_render-0.18.0/src/mesh` and
`tmp/bevy_core_pipeline-0.18.0/src`, compared with `epix_engine/mesh` and
`epix_engine/render/core_graph` (C++23 no-modules build).

This is the source-of-truth tracker for the mesh/core-graph parity effort.
Every row is retained until it is fixed or the user explicitly accepts it as
intentional, deferred, or out of scope.

## Legend

| Status | Meaning |
| --- | --- |
| ✅ | Functionally equivalent |
| ⚠️ | Intentional divergence; rationale recorded |
| ❌ | Present but behavior or API differs; must fix |
| 🚫 | Missing; must implement |
| REVIEW | Audit incomplete; not yet a parity claim |
| N/A | Non-implementable or out of scope, only with user confirmation |

## Translation Rules

| Bevy | Epix |
| --- | --- |
| `Option<T>` | `std::optional<T>` / optional reference wrapper for borrowing |
| `Result<T, E>` | `std::expected<T, E>` |
| ECS resource and system | Epix resource and scheduled system |
| Rust iterator/slice | C++ range/`std::span` view |
| `wgpu` resource wrapper | Direct `wgpu::` resource where that is an accepted Epix convention |

## Mesh Render Asset and Allocator

| ID | Bevy entity / behavior | Epix counterpart | Status | Notes |
| --- | --- | --- | --- | --- |
| M1 | `MeshRenderAssetPlugin`: registers render asset + allocator and initializes vertex layouts | `MeshRenderPlugin` | ❌ | Epix's 2D renderer plugin now installs `MeshAllocatorPlugin` and initializes the render-world `MeshVertexBufferLayouts` alongside `MeshPlugin`, `Core2dPlugin`, and `RenderAssetPlugin<Mesh>` (the C++ counterpart of `RenderAssetPlugin<RenderMesh, GpuImage>`). Plugin composition is close but not identical because Epix batches the whole 2D renderer into `MeshRenderPlugin`; the layout store and allocator are the shared surface, so this stays ❌ only for structure/lifecycle difference. |
| M2 | `RenderMesh`: CPU render metadata, vertex-layout reference, indexed buffer metadata | `RenderMesh` (replaces `GPUMesh`) | ✅ | `GPUMesh` is removed; `RenderMesh` (`vertex_count`, `RenderMeshBufferInfo`, `MeshVertexBufferLayoutRef`, primitive topology) is the `RenderAsset<Mesh>::ProcessedAsset`. Mesh2d draw commands bind the vertex/index buffers from `MeshAllocator::mesh_vertex_slice`/`mesh_index_slice` with the interleaved layout's stride/offsets, and the pipeline cache specializes per interned layout (Bevy Mesh2dPipelineKey's layout id). Verified: 27 mesh + 189 render + text tests, plus client-area captures of mesh_rendering (1280x720, center (174,195,189) — identical to the pre-rework baseline), alpha_mask ((253,160,79)), batching ((42,42,46)), and font_image — all unchanged. |
| M3 | `RenderMeshBufferInfo` | `RenderMeshBufferInfo` | ✅ | The `Indexed { count, index_format }` / `NonIndexed` discriminator now drives the draw (`indexed()`); index format comes from the metadata, and the index buffer+range comes from `mesh_index_slice`. Non-indexed geometry draws `0..vertex_count` from the vertex slice in both mesh and text draw commands. |
| M4 | `RenderAsset<RenderMesh>`: fallible prepare with previous GPU asset and render-asset usage | `RenderAsset<Mesh>` → `ProcessedAsset = RenderMesh` | ✅ | `Mesh` now stores public per-mesh `asset_usage`, requires it at construction, preserves it through `take_gpu_data`, and returns it from `RenderAsset<Mesh>::usage`. Dual-world extraction uses an independent deep copy while render-only extraction transfers the payload. Primitive factories use the Bevy-default `MAIN_WORLD | RENDER_WORLD`; custom/runtime call sites declare their intended usage explicitly. Morph-image retry remains separately tracked by M8, and exact extracted-state/access errors by M9. |
| M5 | `MeshAllocatorPlugin` and `MeshAllocator`: slab allocation, update, free, buffer slices | `MeshAllocatorPlugin` + `MeshAllocator` | ✅ | The public `allocate_and_free_meshes` system now frees removed/modified allocations, allocates every extracted mesh, grows each affected general slab once, then uploads every payload, matching Bevy's three-phase frame flow. `MeshAllocator` is a move-only ready/finish-time resource with public `extra_buffer_usages` and query methods; implementation state and helper types are private/detail-only. General/large buffer usages, pending/resident transitions, actual-buffer `slabs_size()`, slot-capacity rounding, slab-ID sentinel skipping, and first-growth-capacity retention match Bevy. `general_vertex_slabs_supported` is retained; while wgpu-native's C API lacks Bevy's downlevel-flags query, Epix's temporary Vulkan coercion guarantees `BASE_VERTEX`, so `from_world` records true with a colocated removal note. |
| M6 | `MeshAllocatorSettings` | `MeshAllocatorSettings` | ✅ | Settings are a separate render-world resource initialized by `MeshAllocatorPlugin`, preserved when configured before plugin attachment, and passed explicitly into allocation. `MeshAllocator` no longer owns settings, matching Bevy's resource/API boundary. |
| M7 | `MeshBufferSlice`, `SlabId`, allocation query methods | `SlabId`, `MeshBufferSlice`, `MeshAllocator` query methods | ✅ | `SlabId`, `MeshBufferSlice`, and the `MeshAllocator` query methods (`mesh_vertex_slice`, `mesh_index_slice`, `mesh_slabs`, `slab_count`, `slabs_size`, `allocations`) are backed by real offset-allocator-backed allocations and are now consumed by the mesh/text draw commands (device-verified). |
| M8 | Optional morph target extraction and `MorphPlugin` / `inherit_weights` | none | 🚫 | No morph target, `MorphPlugin`, mesh morph-weight components, or inheritance system exists in Epix. This is not yet accepted as out of scope. |
| M9 | `MeshExtractableData` and `MeshAccessError`: distinguish data, absent data, and data already extracted to the render world | Empty attribute/index containers implicitly stand in for extraction state | ❌ | Epix currently treats an empty payload as already extracted, so a newly constructed empty mesh cannot be transferred once, and post-extraction access cannot distinguish missing data from extracted data. Match Bevy's explicit state and fallible access contract; M4's render-asset hook depends on this for exact `AlreadyExtracted` behavior. |
