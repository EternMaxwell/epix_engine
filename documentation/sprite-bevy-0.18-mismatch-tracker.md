## S12: sprite extraction, queueing, batching, and draw commands

| ID | Pinned Bevy behavior | Current Epix behavior | Status | Required alignment |
| --- | --- | --- | --- | --- |
| S12a | `ExtractedSprites` and `ExtractedSlices` are render-world resources cleared and rebuilt each extract; every `ExtractedSprite` stores both main and synced render entity identity | Resource-backed extraction clears and rebuilds both vectors, preserves main/render identities from `RenderEntity`, and creates no temporary render entities | ✅ | Aligned; direct extraction regression checks identity, visibility, clearing, and entity count. |
| S12b | `SpriteAssetEvents` copies every image event during extraction; persistent `ImageBindGroups` drops cached entries for `Unused`, `Modified`, and `Removed`, while `Added` and `LoadedWithDependencies` retain/create lazily | Every event alternative is extracted into `SpriteAssetEvents`; persistent image bind groups invalidate exactly the three destructive alternatives and otherwise populate lazily | ✅ | Aligned; event-copy and per-frame-clear behavior has direct coverage. |
| S12c | `queue_sprites` specializes one pipeline per view key, builds a local set from `RenderVisibleEntities::iter<Sprite>()`, queues resource-backed extracted sprites by main identity, and sets `extracted_index` plus `indexed = true`; GPU-image readiness is not checked here | Queueing consumes `ExtractedSprites` and the typed visible-entity list, specializes per view, defers image readiness, and records the extracted index with indexed drawing | ✅ | Aligned. |
| S12d | `SpriteMeta` owns `RawBufferVec<u32>` index data and an 80-byte vertex-rate `RawBufferVec<SpriteInstance>`; `SpriteBatches` is keyed by `(RetainedViewEntity, batch entity)` and stores image ID plus full instance range | `SpriteMeta` owns the two matching raw buffers and `SpriteBatches` owns per-view, per-entity image/range records | ✅ | Aligned using Epix `RawBufferVec` growth/upload mechanics. |
| S12e | `prepare_sprite_image_bind_groups` walks each sorted transparent phase, treats non-sprite items as batch barriers, batches adjacent equal image IDs, skips missing GPU images, expands sliced sprites, writes phase-head batch ranges, uploads once, and initializes indices `2,0,1,1,3,2` as `u32` | Preparation follows the same phase walk, barriers, image grouping, slice expansion, ranges, and index order while uploading the shared buffers once after CPU preparation | ✅ | Aligned; a two-view regression verifies independent batch ranges and exact indices. Because one representative item draws each image batch, this batching also made the Core2D sort inversion directly visible on screen; it was found and fixed in the same session as C8-D1 of `documentation/mesh-core-graph-bevy-0.18-match-status.md`. |
| S12f | `SetSpriteViewBindGroup<0>` binds the sprite-specific view group with `ViewUniformOffset`; `SetSpriteTextureBindGroup<1>` and `DrawSpriteBatch` look up `(retained view, item entity)`, skip a missing batch, bind the cached image group, bind `u32` indices plus the instance vertex buffer, and draw `0..6` over the batch range | The three commands use the matching slots, dynamic view offset, per-view batch lookup, missing-batch skip, cached image group, `u32` index buffer, instance vertex buffer, and indexed draw | ✅ | Aligned. |
| S12g | Plugin initialization creates `ImageBindGroups`, specialized pipelines, sprite metadata, both extracted resources, event storage, and batches; extraction orders `extract_sprites` in `SpriteSystems::ExtractSprites`; render systems run queue in `Queue`, both preparation systems in `PrepareBindGroups`, and binned Core2D sorting in `PhaseSort` | Plugin initialization and explicitly configured schedules now match this resource and system-set topology | ✅ | Aligned with explicit Epix set registration. |
| S12h | `compute_slices_on_asset_event` runs before Bevy `AssetEventSystems`; changed sprite slices are recomputed in the same `ComputeSlices` set | Image-event recomputation runs in `ComputeSlices` before Epix `AssetSystems::WriteEvents`; sprite-change recomputation remains in the same set | ✅ | Aligned through the documented Epix event-flush adaptation. |
| S12i | `apply_scaling` performs Bevy float arithmetic directly, including its IEEE infinity/NaN behavior for zero texture or quad dimensions | Scaling uses the direct arithmetic without an invented zero guard | ✅ | Aligned; finite and zero-dimension oracle cases are covered. |
| S12x | Bevy has no `CustomRendered` exclusion in sprite extraction | Epix excludes entities carrying the renderer-wide `CustomRendered` marker | ⚠️ | Intentional Epix extension. `CustomRendered` is documented as the standard-renderer opt-out and is applied consistently by sprite, mesh2d, and text extraction. Regression coverage keeps the opt-out explicit. |

## S16: sprite pipeline and shader-visible contract

| ID | Pinned Bevy behavior | Current Epix behavior | Status | Required alignment |
| --- | --- | --- | --- | --- |
| S16a | Public `SpritePipelineKey` encodes HDR, in-shader tonemapping, deband dithering, the eight tonemapping methods, and MSAA in the high three bits; `from_msaa_samples`, `msaa_samples`, and `from_hdr` are part of the API | The public bit-packed key and specialized-pipeline path match the pinned layout and view-key derivation | ✅ | Aligned; exact bit positions, MSAA round trips, and all eight method mappings are covered. |
| S16b | `SpritePipeline` owns descriptor-backed view and material layouts plus one shader handle. Group 0 contains dynamic `ViewUniform` and LUT texture/sampler; group 1 contains texture then filtering sampler | Render startup creates the matching two layouts and one embedded shader handle, reusing CoreGraph's LUT binding helpers | ✅ | Aligned. |
| S16c | The sole 80-byte instance vertex layout is three transposed affine columns, linear color, and UV offset/scale at locations 0-4. The shader derives quad position and UV from `vertex_index`; no quad vertex buffer or position-size payload exists | The sole instance-rate stream has the exact 80-byte field layout; transforms bake sprite geometry and the shader derives corners from the vertex index | ✅ | Aligned; size, offsets, transpose, and index order are asserted. |
| S16d | LDR views optionally tonemap in the sprite fragment shader using view color grading and the selected LUT; debanding is emitted only with in-shader tonemapping. HDR views skip in-shader tonemapping. | The Slang sprite shader imports the shared CoreGraph tonemapping module, selects all eight methods for LDR views, carries the pinned deband specialization flag, and bypasses in-shader tonemapping for HDR | ✅ | Aligned; a real eight-viewport LDR example verifies visibly distinct method selection. |
| S16e | Specialization chooses HDR format or Bevy-default sRGB, alpha blending, Core2D depth format with no writes and `GreaterEqual`, key-derived MSAA, and no extra geometry buffers | Specialization derives the target, blend, Core2D depth state, and multisampling from the key and declares only the single instance vertex stream | ✅ | Aligned; the complete descriptor is asserted. |

| S11 | Wireframe2d | ⚠️ | **Closed 2026-10 (commit `d88916fb`), reopened as S11-D1 on 2026-10.** `Wireframe2dPlugin` is ported with Bevy's binned phase item and keys, the `PolygonMode::Line` mesh2d variant, the real 16-byte fragment push-constant colour, the node between `EndMainPass` and `PostProcessing`, and the full config/marker/material surface. **S11-D1 (open): the wireframe transform is nondeterministic across runs.** Three consecutive captures of `sprite_render/examples/header/wireframe2d.cpp` put the triangle's global wireframe on the triangle twice and on the circle once (pixel `(220,360)` is the grey line `#9D9D9E` in two runs and the background `#2B2C2F` in the third, with the line instead appearing at `(740,360)`). Mechanism: every queue site passes `InputUniformIndex{}` — Bevy's `queue_wireframes` does the same (`wireframe2d.rs:864`) — but that is only sound when the binned phase's per-bin instance indices coincide with the `Mesh2dUniform` slots. `GetFullBatchData<Mesh2dPipeline>::get_binned_index` declines ("only intended for GPU mesh uniform building, which is not implemented for 2d meshes", `mesh2d_pipeline.hpp:630`), so nothing computes the per-entity uniform index; the phase's bin-insertion order and the batching system's uniform upload order can disagree, and which entity lands on slot 0 depends on hash-map iteration. |
| S14 | Tilemap chunk and material | ✅ | **Closed 2026-10.** Ported item by item from `bevy_sprite_render/src/tilemap_chunk/{mod.rs,tilemap_chunk_material.rs,tilemap_chunk_material.wgsl}`: `TilemapChunk` (with the `on_insert_tilemap_chunk` hook that builds the chunk mesh, the `Rgba16Uint` tile-data image and the material, then attaches `Mesh2d` + `MeshMaterial2d`), `TilemapChunk::calculate_tile_transform`, `TileData`/`from_tileset_index`, `TilemapChunkTileData`/`tile_data_from_tile_pos`, `TilemapChunkMeshCache`, `PackedTileData` (the 8-byte GPU ABI), `make_chunk_tile_data_image`, `TilemapChunkMaterial` (2d-array tileset + sampler + `u_int` tile-data texture), `update_tilemap_chunk_indices`, `TilemapChunkPlugin` and `TilemapChunkMaterialPlugin` on the shared Slang shader `embedded://sprite/tilemap_chunk_material.slang`. `SpriteRenderPlugin` now adds `Mesh2dRenderPlugin`, `ColorMaterialPlugin`, `TilemapChunkPlugin` and `TilemapChunkMaterialPlugin` exactly as Bevy's (`lib.rs:71-76`), which its examples previously added by hand. Verified by 11 tests in `sprite_render/tests/header/tilemap_chunk_tests.cpp` and the `sprite_render/examples/{header,module}/tilemap_chunk.cpp` capture. **Recorded divergences:** `#[component(immutable)]` and `#[reflect(..)]` have no Epix counterpart; the hook inserts directly (Epix's `Parent::on_insert` idiom) instead of through `world.commands()`, and warns instead of panicking when a component or asset store is missing; `TileData::color` is a linear `glm::vec4` packed through the sRGB transfer Bevy's `Color::to_srgba()` applies, since Epix has no `bevy_color`; default texture handles are `image::DEFAULT_IMAGE_HANDLE`; Bevy's mesh cache is read but never populated, which is reproduced verbatim so a chunk of a new size allocates its mesh. |
